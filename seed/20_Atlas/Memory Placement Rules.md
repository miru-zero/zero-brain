# Memory Placement Rules — ของแต่ละอย่างควรอยู่ที่ไหน

## ตัดสินใจตามลำดับนี้

1. **ยังไม่ได้คิด / กันหลงลืม / ดิบมาก?**
   → `00_Fleeting/` ผ่าน `zero_capture` — ต้องถูกจัดการใน 7 วัน

2. **เป็นแผนที่/ดัชนี/กฎ/สถานะปัจจุบันของระบบ?**
   → `20_Atlas/` (เช่น Home, Today, Hotcache, เอกสารกฎ)

3. **เป็นแหล่งอ้างอิงดิบ (บทความ เอกสาร ไฟล์ dump)?**
   → `30_Sources/` — ถ้าสรุปเป็นองค์ความรู้แล้วให้เขียนโน้ตแยกใน `10_Notes/` แล้วลิงก์กลับมา

4. **เป็นองค์ความรู้ถาวร?** → `10_Notes/` ผ่าน `zero_write_note` เลือก type:
   - `atomic` — ความคิดเดียว ยืนหยัดได้เอง (ต้องมี evidence)
   - `entity` — คน/องค์กร/สิ่งของ/โปรเจกต์ที่มีตัวตน (ต้องมี evidence)
   - `source` — บันทึกอ้างอิงแหล่งที่มา
   - `log` — บันทึกเหตุการณ์ตามเวลา (ทำอะไร เมื่อไหร่ ผลยังไง)
   - `moc` — Map of Content โน้ตประเภท "สารบัญ" รวมลิงก์หัวข้อเดียวกัน

5. **เป็นแบบฟอร์มที่ใช้ซ้ำ?**
   → `40_Templates/base/`

6. **เป็นของระบบ (snapshot, ไฟล์ kernel)?**
   → `99_System/` หรือ `.kb/` — ห้ามยุ่งด้วยมือ ให้ tools จัดการ

## กฎเสริม

- **ทุกโน้ตใหม่ต้องมี inbound link ≥ 1** — ลิงก์จาก index, MOC หรือโน้ตที่เกี่ยวข้อง (`zero_link`)
- ไม่แน่ใจ → ใส่ `00_Fleeting/` ก่อน แล้วค่อยตัดสินในรอบ nightly
- ห้ามเก็บ credentials / tokens / PII ดิบ — อ้าง "ตำแหน่ง" ของมันแทนค่าจริง
- ชื่อไฟล์โน้ตถาวร: server สร้างให้อัตโนมัติ `<id> - <slug>.md` — อย่า rename เอง
